# Flat Directory Input, Two-Pass Batch Shared Runtime Aggregation, and Package-Relative Python Runtime Imports

`parsmith check` and `parsmith generate` (along with the Rust, Python, and Node-API SDKs) accept an arbitrary list of `.kdl` file and directory paths, expanding directories via a deterministic flat scan (`dir/*.kdl`) rather than recursive tree walking so that a package directory maps 1:1 to a single target namespace and shared `<runtime_name>.<ext>` module while allowing shared helper files in subdirectories or prefixed with `_` (`_*.kdl`) to be pulled in exclusively via `import`. During batch codegen, modules that declare no runtime artifacts (`structs.is_empty() && functions.is_empty() && json_defs.is_empty()`, such as pure `define` or `extension` libraries) emit no standalone parser file, and `-R / --separate-runtime` executes in two passes: Pass 1 compiles all input schemas and merges their `ModuleBuilder` helper sets (`std_defs`, `std_imports`, `runtime_defs`, `runtime_imports`, checking `E400` conflicts) and capability flags (`has_html`, `has_xpath`, `has_table`, `uses_http`, `has_fetch`, `has_rest`, `json_defs`) to emit a single unified `<runtime_name>.<ext>`, and Pass 2 writes each parser module—preventing the last schema in alphabetical order (e.g., a pure-HTML `@request` schema or a pure-REST `(rest)struct` schema) from overwriting `<runtime_name>.<ext>` with a tree-shaken subset that breaks sibling parsers. Finally, Python's default `--runtime-name` is `.parsmith_runtime`, emitting package-relative `from .parsmith_runtime import ...` out of the box when `-R` is used while preserving absolute `from <name> import ...` when `--runtime-name` is explicitly passed without a leading dot.
