# Loopback HTTP Server and Structural HTML Fixtures for Cross-Target E2E Testing

End-to-end tests in `tests/integration/` exercise generated Python (`py-bs4`, `py-lxml`, `py-parsel`, `py-selectolax`) and JavaScript/TypeScript (`node` + `jsdom`) modules against offline **structural HTML fixtures** and a single in-process `http.server.ThreadingHTTPServer` (`tests/fake_server.py`) bound to `127.0.0.1:0` (also runnable standalone via CLI), rather than per-library HTTP mock interceptors (`respx`, `aioresponses`, `responses`) or full raw web page dumps. Rewriting the KDL `@request` host to the loopback server address prior to codegen allows a single deterministic route table to test all real transport factories (`via_urllib`, `via_httpx`, `via_httpx_async`, `via_requests`, `via_aiohttp`, and Node.js `viaFetch`) over real TCP sockets—covering query array styles, cookies, headers, form/JSON bodies, `response-path`, `response-join`, discriminated `@error` / `@error:<suffix>` fallthrough, `UnknownErr`, `DecodeErr`, and `TransportErr`. HTML fixtures retain 100% authentic DOM hierarchies and formatting quirks (`&nbsp;`, multi-valued attributes, embedded `__NEXT_DATA__` and `Playerjs` scripts) trimmed to 3–4 controlled items so every fixture deterministically exercises both happy-path extraction and missing-element `fallback` / nullability paths.
