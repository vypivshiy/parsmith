# JS/TS Node-API (`napi-rs`) Host SDK, Hybrid Native Loader, and Dual Serialization Contracts

`crates/parsmith-js` exposes `parsmith` to JavaScript and TypeScript runtimes (Node.js, Bun, Deno) over the stable Node-API C ABI (`napi-rs` `cdylib`), paired with a dual CommonJS/ESM package in `js/` (`index.cjs`, `index.mjs`, `index.d.ts`). To keep Cargo workspace development self-contained without mandatory global JS build steps, `js/index.cjs` resolves prebuilt `parsmith.<platform>.node` binaries when present and falls back to loading the compiled shared library directly from `target/{release,debug}/{parsmith_js.dll,libparsmith_js.so,libparsmith_js.dylib}` as a Node-API addon. The JS SDK mirrors all 20 classes of `parsmith-py` (`Diagnostic`, `CheckResult`, `CodegenOptions`, `GenerateResult`, `ModuleInfo`, and its 15 introspection child classes) with idiomatic `camelCase` getters/methods, defaults `CodegenOptions.target` and `generate()` to `"ts"`, accepts `string | URL` for `sourceOrPath` and `Record<string, string> | Map<string, string>` for in-memory VFS `sources`, accepts `camelCase`, `snake_case`, and `kebab-case` keys in option objects, and enforces a dual serialization contract on every class: `toObject()` and `toJSON()` produce plain `camelCase` JS objects matching `index.d.ts`, `toDict()` produces `snake_case` dictionaries matching `parsmith-py`, and `formatJson()` / `toJson()` emit canonical `parsmith` JSON.
