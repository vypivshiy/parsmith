# Formal CSS Grammar Validation and Portable Regex Subset

CSS selector validation in `parsmith` checks only formal CSS3/CSS4 syntax (balanced delimiters, combinators, attribute operators, and structural `:not` / `:is` / `:where` / `:has` / `:nth-*` inner grammar) without allowlisting or denylisting `:pseudo-class` or `::pseudo-element` identifier names, because target DOM engines across ecosystems support different selector extensions. Conversely, regular expression validation enforces a restricted **portable regex subset**: `(?x)` verbose patterns are automatically normalized into single-line expressions, lookarounds (`(?=...)`, `(?!...)`, `(?<=...)`, `(?<!...)`) and named capture groups (`(?P<name>...)`, `(?<name>...)`) are rejected (`E002`), and pipeline `re` / `re-all` require a single unnamed capture group (`E001`), ensuring every schema compiles cleanly to linear-time DFA/NFA engines in Go (`regexp`) and Rust (`regex`) as well as Python and JS/TS.
