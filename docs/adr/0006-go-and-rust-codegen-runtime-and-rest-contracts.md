# Go and Rust Target Codegen, Inline vs Separate Runtime, and Native REST Contracts

`GoEmitter` (`goquery` + `net/http` + `gjson`) and `RustEmitter` (`dom_query` + `serde` + `reqwest`) emit pre-formatted source directly from `CodeWriter` without invoking external `gofmt` or `rustfmt` subprocesses at compile time, defaulting to self-contained single-file output (`<stem>.go` with selective `std*` helpers; `<stem>.rs` with an inline `pub mod rt` that omits `dom_query` when `!module_has_html`) while supporting `-R / --separate-runtime` (`<runtime_name>.go` in the same package and `<runtime_name>.rs` via `use super::<runtime_name> as rt;`) for multi-schema packages and crates. Unlike Python and JS/TS—which abstract multiple third-party HTTP libraries behind `SyncTransport` / `AsyncTransport`—Go and Rust bind directly to their ecosystem-standard clients (`*http.Client` with `sscReqOpt` in Go; `&reqwest::Client` in Rust) while preserving strict cross-target semantic parity: (1) REST responses failing JSON parsing or `JsonDef` projection surface as a dedicated `*DecodeErr` struct in Go and `<Struct>Error::Decode(u16, rt::SscError)` variant in Rust rather than collapsing into `UnknownErr` / `Unknown`; (2) Go `UnmarshalJSON` validates root object structure and `gjson.Result` value types (`String`, `Number`, `True`/`False`, array/object) instead of relying on `gjson`'s silent type coercion; and (3) both targets enforce ADR-0004 DOM, attribute, Unicode rune/char slicing, full entity/escape `unescape`, and `E203` XPath rejection contracts.
