# Unified `rt` Runtime Prefix Across Python, TypeScript/JavaScript, Go, and Rust Targets

All compiler-synthesized runtime functions, error classes, option types, allowlist JSON projectors, table row sentinels, DOM utility aliases, and REST error matcher tables use a single canonical `rt` namespace prefix across all four target ecosystems (`rt_<snake>` / `Rt<Pascal>` / `RT_<UPPER>` in Python; exported `rt<Pascal>` / `Rt<Pascal>` / `RT_<UPPER>` with `.d.ts` declarations in TypeScript and JavaScript; package-private `rt<Pascal>` and exported `RtHttpOption` in Go; and `pub mod rt` with `rt::RtError` and `RT_<UPPER>` in Rust), superseding the historical mix of `std_*`/`std*`, legacy `ssc_*`/`ssc*`/`Ssc*`, and bare leading-underscore `_` identifiers. We chose `rt` ("runtime") over `std` and `ps` because `std` collides with the Rust standard library crate (`::std`) and reads misleadingly on schema-specific generated projectors (`rt_project_<schema>` / `rtProject<Schema>`) and error classes (`RtJsonError`, `RtAssertionError`), while stripping leading underscores (`_`) ensures that all runtime helpers can be cleanly imported across `--separate-runtime` modules in Python, exported from ES modules with full `.d.ts` typing in JS/TS, and shared across package files in Go without colliding with user-defined schema symbols. Public HTTP transport and monadic REST result contracts (`HttpRequest`, `RawResponse`, `TransportError`, `SyncTransport`, `AsyncTransport`, `HttpTransport`, `AxiosLike`, `*Transport`, `via_*` / `viaFetch` / `viaAxios`, `WithHeader*` / `WithParam*` / `WithCookie*` / `WithTimeout`, `Ok`, `UnknownErr`, `TransportErr`, `DecodeErr`, `ErrMatcher`) remain unprefixed as ergonomic user-facing API types.
