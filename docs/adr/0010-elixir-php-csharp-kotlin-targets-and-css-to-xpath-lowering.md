# Elixir, PHP, C#, and Kotlin Target Backends and Compile-Time CSS-to-XPath Lowering

`parsmith` extends its target matrix with four server ecosystems—`ElixirEmitter` (`elixir`/`ex`: `Floki` + Elixir 1.18–1.20+ `JSON` + Erlang/OTP 27–29 `:httpc` and `via_req`), `PhpEmitter` (`php`: PHP 8.1+ `readonly class` models with `--html-lib native|dom-crawler`, `json_decode`, and `ext-curl` / stream transport), `CSharpEmitter` (`csharp`/`cs`: .NET 8+ `sealed record` models, `AngleSharp` + conditional `AngleSharp.XPath`, `System.Text.Json`, and `HttpClient`), and `KotlinEmitter` (`kotlin`/`kt`: Kotlin 2.x `data class` models, `Jsoup` CSS + XPath, `kotlinx.serialization.json`, and `java.net.http.HttpClient`)—all supporting single-file inline `Rt` emission, `-R / --separate-runtime`, and `--package` (`--namespace`). Because PHP's standard `ext-dom` (`\DOMDocument` + `\DOMXPath`) on PHP 8.1–8.3 natively evaluates XPath 1.0 but lacks CSS selector queries until PHP 8.4's `\Dom\HTMLDocument`, `parsmith` implements compile-time CSS3-to-XPath 1.0 lowering for `php --html-lib native` (the default PHP backend), enabling zero-Composer HTML and XPath extraction across PHP 8.1–8.5+ while emitting `E002` with a hint to use `--html-lib dom-crawler` (`symfony/dom-crawler` + `symfony/css-selector`) when a selector uses CSS4 features that cannot be lowered to XPath 1.0. To preserve 100% backward compatibility for existing `.kdl` schemas across all 8 ecosystems, codegen emitters automatically escape target-language reserved words (`@ident` in C#, `` `ident` `` in Kotlin, `$ident` properties in PHP, and safe function/key naming in Elixir) just like `RustEmitter` (`r#ident`), restricting `E403` diagnostics to identifiers that cannot be escaped in the target grammar.
