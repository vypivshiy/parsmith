# Postfix Go-Style Field Types, Auto-Cast, and Constant `value=` Injection Across `struct` and `json`

`parsmith` standardizes field declarations across `struct`, `@init`, and `json` schemas on postfix Go-style type specifiers and a `value=<literal>` property (`<field> [<type>] [value=<literal>] [{ <pipeline> }]`), keeping KDL 2.0 parenthesized annotations (`(...)`) strictly reserved for structural and container modifiers (`(list)struct`, `(raw)struct`, `(rest)struct`, `(array)json`, `(dict)json`, `(array)str`). In KDL 2.0 (§3.10), a node permits at most one `(type)` annotation before its name and forbids `[`, `]`, `(`, and `)` inside bare identifiers, which makes prefix array annotations like `(str[])tags` or `(array)(str)tags` syntax errors (`E000`) and causes LLM agents to hallucinate invalid KDL when mixing prefix `(str)field` in `struct` with postfix `field str` in `json`. Under the unified postfix grammar, `json` fields require `<type>` while `struct` and `@init` fields treat `<type>` (`str`, `int`, `float`, `bool`, `?`, `(array)`) as optional: when omitted, `parsmith` infers the field type from `value=<literal>` and the pipeline's `OpSig` chain; when declared on a pipeline field, lowering automatically inserts `to-bool` (`Any -> BOOL`), `to-int` (`STRING -> INT`), or `to-float` (`STRING -> FLOAT`) ahead of any terminal `fallback` and verifies the final `TypeInfo` (`E100`, never implicitly extracting `text` from `DOCUMENT`). Finally, `value=<literal>` (`str` with `{{DEFINE}}` expansion, `int`, `float`, `bool`) injects constant values into `json` projectors without reading wire JSON and seeds `StepOp::Value` at step 0 in `struct` and `@init` pipelines (either as a standalone constant field without `{}` or piped into subsequent operations such as `!Namespace.op`), preserving the uniform `_parse_<field>(v)` method signature across all 9 target backends.
