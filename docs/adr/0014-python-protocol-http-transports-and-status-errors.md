# Structural `Protocol`-Typed Python HTTP Adapters, Explicit Client Injection, and Unified `HttpStatusError`

Python's generated HTTP transport runtime (`crates/parsmith/src/codegen/python/runtime/http_transport.py`) drops all `importlib.import_module(...)` dynamic imports in favor of minimal, public `typing.Protocol` interfaces (`HeadersLike`, `HttpResponseLike`, `AiohttpResponseLike`, `HttpxLike`, `AsyncHttpxLike`, `RequestsLike`, `AiohttpLike`) and mandatory pre-configured client/session arguments on `via_httpx(client)`, `via_httpx_async(client)`, `via_requests(session)`, and `via_aiohttp(session)` (matching TypeScript's `viaAxios(instance: AxiosLike)` while keeping stdlib `via_urllib(timeout=None)` zero-argument). Removing hardcoded module names and client construction simplifies the runtime, forces callers to explicitly configure lifecycle/connection pooling/timeouts/proxies on their own client instance, and unifies `httpx` and `httpx2` (as well as `requests`-compatible forks such as `curl_cffi` and `niquests`) under the same sync/async factories without runtime `inspect.iscoroutinefunction` dispatch.

## Considered Options

- **Keep `client=None` via `importlib` or inline `try: import httpx2 ... except ImportError: import httpx`**: Rejected because it couples generated zero-dependency modules to package name guessing, triggers `mypy --strict` `import-not-found` errors when optional clients are absent, and encourages per-request unpooled clients.
- **Single `@overload`-ed `via_httpx(client)` dispatching sync vs. async at runtime**: Rejected because a single Python `Protocol` cannot declare both `def request` and `async def request`, and `inspect.iscoroutinefunction` fails on sync wrapper callables that return awaitables.
- **Exclude `ValueError` alongside `(TypeError, AttributeError)` when wrapping `TransportError`**: Rejected because `aiohttp.ClientConnectorCertificateError` inherits from `ssl.SSLCertVerificationError -> ValueError`; re-raising only `(TypeError, AttributeError)` preserves real TLS/certificate failures as `TransportError` while letting invalid kwargs and broken mocks surface immediately.

## Consequences

- **Exception boundary**: Built-in third-party Python adapters wrap only the client I/O block (`client.request(...)` and `await resp.text()` in `aiohttp`) with `except (TypeError, AttributeError): raise` followed by `except Exception as e: raise TransportError(e) from e`, eliminating library-specific exception imports (`httpx.HTTPError`, `httpx2.HTTPError`, `requests.RequestException`, `aiohttp.ClientError`) while keeping `rt_rest_call` strictly catching only `TransportError`.
- **Unified HTTP `>= 400` handling without `raise_for_status()`**: Transport adapters never call `resp.raise_for_status()`; instead, HTML/`(raw)struct` fetch helpers (`rt_fetch`, `rt_fetch_async`) check `if resp.status >= 400: raise HttpStatusError(resp)`—matching Rust, Elixir, C#, and Kotlin—while `(rest)struct` endpoints continue routing all status codes through `rt_dispatch_response` (`Ok`, `@error`, `DecodeErr`, `UnknownErr`).
- **Separate runtime exports (`-R`)**: All seven `*Like` protocols and `HttpStatusError` are exported in `HTTP_TRANSPORT_RUNTIME_SYMBOLS` so downstream callers and strict `mypy` suites can annotate wrappers and catch `HttpStatusError` directly.
